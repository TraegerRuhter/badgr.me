# Build plan: reminder-editing parity with Due

**Status:** spec frozen, nothing built. Derived from a 90-second screen
recording of Due for iOS (§1). Section numbers here are referenced from code
comments — cite them rather than restating the reasoning inline.

The goal is **not** to clone Due. It is to import the handful of interaction
patterns Due gets right (§2) into badgr's existing model, using badgr's own
vocabulary, and to stop shipping controls that make the user do arithmetic in
their head.

---

## 0. Scope and non-goals

**In scope.** The task create/edit surface on both clients: how a fire time is
chosen, how the nag schedule is configured, how the consequences of those
choices are shown back to the user before they commit.

**Explicitly not in scope.**

| Not doing | Why |
| --- | --- |
| Cloning Due's names — "Nag-Me", "DayMinder", "Actionable Snooze" | badgr has its own voice, and `nagIntervalSeconds` is already the field name. Copying a competitor's product vocabulary buys nothing and invites confusion |
| Due's visual design (green accent, iOS grouped tables) | badgr wears the badger's coat (`packages/ui/src/tokens.ts`). Patterns transfer; palettes don't |
| RRULE-grade recurrence | `repeat.ts` deliberately ships four cadences. That decision stands |
| The task list, notification presentation, widgets | Different surfaces, different sessions |
| iPad/desktop layout | The recording is a phone. Don't infer wide-layout behaviour from it |

## 2. UX invariants

Numbered because each one gets a test that fails the build if broken. These are
the actual deliverable; the screens in §3 are just where they show up.

- **U1 — Every schedule-producing control states its consequence in the same
  view.** Not in a tooltip, not on the next screen. If a control changes when
  the phone will buzz, the view says when it will buzz.
- **U2 — Preview text is generated by the scheduler, never alongside it.** The
  sentence "will fire at 12:00, 13:00, 14:00" must come from `computeNagBurst`
  output, formatted. A second, parallel implementation that computes fire times
  for display is forbidden: it will drift, and the drift will be invisible until
  a user is woken at the wrong hour. **This is the single most important
  invariant in this document.**
- **U3 — A time in the past is a visual state, not a blocked action.** Setting a
  reminder for a past time is legitimate (it fires immediately). Show it in
  `colors.danger`; do not disable Done, do not open a dialog.
- **U4 — Help text follows state.** Where a toggle changes what a feature does,
  the explanatory copy changes with it.
- **U5 — Cross-feature interactions are stated in the UI, not just the code.**
  If snoozing resets the nag burst, the nag screen says so.
- **U6 — No new per-task option may exceed the notification budget.** Every
  option that adds pre-scheduled fires is accounted for in
  `allocateNotificationBudget` before it ships. The 60-slot ceiling
  (`SAFE_GLOBAL_NOTIFICATION_BUDGET`) is not negotiable.
- **U7 — Both clients render the same string from the same core function.**
  Label text lives in `@alarmed/core`, never duplicated in `apps/*`.

## 3. The reference flow, screen by screen

Observed behaviour. Timestamps cite the contact sheets in §1.

### 3.1 Root editor (0–34 s)

Nav bar `Cancel · New Reminder · Done`. Then, top to bottom:

1. **Title field** — plain text, no placeholder visible once filled.
2. **Alarm row** — label left, value right-aligned. Tapping the row
   collapses/expands the inline picker below it (collapsed state visible at
   ~10 s). The value is the *only* thing that turns red when past-due (§3.5).
3. **Inline date/time picker**, three stacked bands:
   - Preset time chips: `07:00 | 12:00 | 17:00 | 21:00`. Tapping one sets the
     time of day, leaving the date untouched.
   - Three-column wheel: date (`Fri Sep 4`) · hour · minute. Standard iOS
     picker feel — centre row large and dark, neighbours faded.
   - Quick chips: `Today | +3 Hours | +1 Week | Calendar`.
4. **Calendar chip** swaps the wheel band for a month grid (August 2026, today
   ringed in red) — same row position, not a new screen.
5. **More Options** — a centred green row that expands the full option list.

### 3.2 Expanded options (34 s onward)

Grouped sections, in this order:

```
Category                          None >
DO-IT / DELAY-IT OPTIONS
  Nag-Me                     Every 20m, 12 times >
  Actionable Snooze                 (15 min) >
REPEAT OPTIONS
  Repeat                            Never >
  DayMinder                    Every 1h for 2h >
ALARM OPTIONS
  Melody                      (Ivory Tune) >
  Alert Message                     [toggle on]
  Sound                             [toggle on]
PRE-ALARM OPTIONS
  Lead Time                   Pre-Alarm Off >
NOTES
```

Every row's right-hand value is a **derived summary**, not a raw setting.

### 3.3 Nag-Me (40–52 s)

A pushed screen. Options, each with a computed subtitle:

| Option | Subtitle |
| --- | --- |
| Default | Off |
| Nag-Me Off | — |
| Every minute (Relentless) | repeats until marked done |
| Every 5 minutes | repeats 6 times (30 min) or until marked done |
| Every 15 minutes | repeats 6 times (90 min) or until marked done |
| Every 30 minutes | repeats 6 times (3 hours) or until marked done |
| Every hour | repeats 6 times (6 hours) or until marked done |
| Every day | repeats until marked done |
| Custom | *live-computed* |

Selecting **Custom** reveals an inline wheel (`0 hours` / `N min`) plus a
stepper row `Nag-Me N times [−][+]`. The subtitle recomputes on every change —
observed: 3 min × 3 → "(9 min)", 20 min × 3 → "(1 hr)", 20 min × 11 →
"(3 hr, 40 min)", 20 min × 6 → "(2 hr)", 20 min × 12 → "(4 hr)".

Footer: an explanation, then "**NOTE:** Nag-me will be reset (start over) if
you snooze or adjust the date/time for the reminder." — this is U5 in the wild.

### 3.4 DayMinder (64–78 s)

Intra-day recurrence. Distinct from Repeat.

- `REPEAT EVERY` — `1 hour` with a `[−][+]` stepper.
- `FOR` — segmented `Off | Count | Duration`.
  - **Off** → body reads "DayMinder Off"; nothing else shown.
  - **Count** → `2 times [−][+]`.
  - **Duration** → `2 hours [−][+]`.
  - Count and Duration both print: "Based on a start time of 12:00, reminder
    will fire at 12:00, 13:00, 14:00" — **actual fire times, enumerated**.
- `AutoComplete` toggle, default on. Flipping it rewrites the body copy:
  - on → "…will repeat the DayMinder at regular intervals."
  - off → "Reminder will fire based on when each DayMinder recurrence is marked
    as completed."
- An `(i)` button in the nav bar for the long-form explanation.

### 3.5 Past-due affordance (observed ~12–14 s)

When the selected time is in the past, two things change together:

1. The Alarm value turns **red**.
2. The first quick chip changes `Today` → `Now`.

No dialog, no disabled Done. Cheapest possible correctness signal.

### 3.6 Other screens

- **Actionable Snooze** (58 s) — Default (15 minutes) ✓, 15m, 30m, 1h, 3h, 1d,
  Custom. Footer explains it applies to interactive notifications.
- **Category** (36 s) — None ✓, Home (blue), Work (green), Shopping (orange),
  with an `Edit` affordance. Footer: "Tap the Edit button above to change,
  arrange, add, delete categories."
- **Lead Time** (82 s) — inline wheel, number × `Minute | Hour | Day`.

## 4. What badgr already has

**The important finding: most of §3.3 needs no schema change.** `Task` already
carries the fields Due's Nag-Me configures.

| Due concept | badgr equivalent | Status |
| --- | --- | --- |
| Nag-Me interval | `Task.nagIntervalSeconds` | exists |
| Nag-Me repeat count | `Task.nagMaxCount` | exists |
| "until marked done" | `nagMaxCount: null` | exists |
| Nag-Me off | `Task.dismissedAt` (pause) / `escalationMode` | partial — see §9.1 |
| Repeat | `Task.repeatRule` + `repeat.ts` | exists (4 cadences) |
| Actionable Snooze | `AppSettings.nag.snoozeMinutes` | **global only**, not per-task |
| Lead Time / Pre-Alarm | — | **new field** |
| DayMinder | — | **new fields** |
| Category | — | **new** (note: `sections.ts` is list grouping, not categories) |
| Melody / Sound / Alert Message | — | out of scope for now |

So Phases 1–3 below are **presentation work over the existing model**. Schema
changes don't start until Phase 4, and each one must clear U6.

## 5. The derived-label engine

The centrepiece, and the reason to do this at all. One pure module in
`packages/core/src/describe.ts`, exported from the barrel.

```ts
/** "Every 20 min, 12 times (4 hr)" — the Custom subtitle in §3.3. */
export function describeNagPlan(input: {
  intervalSeconds: number;
  maxCount: number | null;
  escalationMode: EscalationMode;
}): string;

/** "repeats 6 times (30 min) or until marked done" — preset subtitles. */
export function describeNagPreset(preset: NagPreset): string;

/** "will fire at 12:00, 13:00, 14:00" — MUST derive from computeNagBurst (U2). */
export function describeFireTimes(
  burst: Date[],
  opts?: { max?: number; locale?: string }
): string;

/** "in 2 hours" / "3 hours ago" — for the past-due state (§3.5). */
export function describeRelativeFireTime(fireAt: Date, now?: Date): string;

/** Whether §3.5's red-and-"Now" state applies. */
export function isPastDue(fireAt: Date | null, now?: Date): boolean;
```

Constraints on this module:

- **Pure.** No `Intl` locale sniffing from the environment — take a locale
  argument and default it, so tests are deterministic across machines.
- **Duration formatting is one function.** "(3 hr, 40 min)" and "(90 min)" and
  "(4 hr)" are the same formatter with different inputs. Do not write three.
- `describeFireTimes` takes an already-computed burst. It does not compute one.
  That signature *is* the enforcement mechanism for U2 — there is no way to
  call it without having run the real planner first.

## 6. Phases and gates

Each gate is blocking. No phase starts until the prior gate is signed off.

**Phase 1 — Derived-label engine.** `packages/core/src/describe.ts` per §5.
No UI, no schema change.
*Gate: unit tests cover every duration boundary (59 s, 60 s, 90 min, 24 h) and
every §3.3 preset string; `describeFireTimes` is proven to accept only real
planner output.*

**Phase 2 — Nag presets + past-due affordance.** Wire §3.3's preset list and
§3.5's red/"Now" behaviour into the existing Edit sheet on both clients. Still
no schema change — presets are just `(nagIntervalSeconds, nagMaxCount)` pairs.
*Gate: identical label strings on web and mobile (U7), asserted by a shared
test, not by eyeballing.*

**Phase 3 — Progressive disclosure.** Restructure the Edit sheet into §3.2's
collapsed-by-default shape with a "More Options" expansion. Inline the date
picker per §3.1.
*Gate: every existing edit flow still reachable in the same or fewer taps —
enumerate them before starting, verify after.*

**Deliberate deviation from Due.** Due puts Nag-Me behind More Options, because
Due is a general reminder app where nagging is one feature among many. badgr's
entire premise is badgering, so the nag presets stay on the top level and Notes
and Repeat move behind the disclosure instead. §0 says import the patterns, not
the layout; this is that distinction in practice.

Flow inventory taken before the restructure (the gate's "before"):

| # | Flow | Taps from editor open, before |
| --- | --- | --- |
| 1 | Edit title | 0 (focus and type) |
| 2 | Edit notes | 0 |
| 3 | Add checklist item | 1 |
| 4 | Toggle has-a-date | 1 |
| 5 | Set exact date/time | 1 (native picker) |
| 6 | Time-of-day chip (07:00/12:00/17:00/21:00) | 1 |
| 7 | Today / +1 day / +1 week | 1 |
| 8 | Set repeat cadence | 1 |
| 9 | Pick a nag preset | 1 |
| 10 | Custom interval | 2 (Custom, then chip) |
| 11 | Custom count | 2 (Custom, then stepper) |
| 12 | Until-marked-done | 2 |
| 13 | Shrink intervals | 2 |
| 14 | Save / Cancel | 1 |

Flows 2, 3 and 8 gain one tap (the More-options disclosure). Everything else is
unchanged, and the default view drops from fourteen controls to six.

**Phase 4 — Per-task snooze and lead time.** Adds `Task.snoozeSeconds`
(nullable, null = fall back to the global setting) and `Task.leadTimeSeconds`.
Lead time adds a *second* pre-scheduled notification per task.
*Gate: `allocateNotificationBudget` accounts for pre-alarms and a test proves
the 60-slot ceiling holds with every task carrying a lead time (U6). Sync
round-trips both fields through `reconcileTasks` unchanged.*

**Phase 5 — Intra-day recurrence (badgr's DayMinder).** §3.4. New fields for
interval, and a count-or-duration cap. AutoComplete semantics are the hard part:
"fire on a schedule" vs "fire when the previous one is completed" are different
scheduling models, and the second cannot be fully pre-armed.
*Gate: the enumerated fire-time preview matches `computeNagBurst` output exactly
for 20 randomised configurations (U2). Autocomplete-off is either implemented
or visibly absent — no half-working state.*

**Phase 6 — Categories.** §3.6. New entity, list filtering, colour tokens.
*Gate: categories survive a sync round-trip and a soft delete.*

## 7. Test strategy

- **String snapshots** for every label in §3.3 and §3.2. These are the product;
  regressions here are silent otherwise.
- **Boundary tests** on duration formatting: 59 s, 60 s, 61 s, 89 min, 90 min,
  23 h, 24 h, 25 h. Due prints "(90 min)" not "(1 hr, 30 min)" — decide badgr's
  rule (§9.2) and pin it.
- **U2 enforcement test**: assert `describeFireTimes` output matches a
  `computeNagBurst` run for the same config. If someone adds a parallel
  formatter, this fails.
- **U6 budget test**: N tasks × every new option enabled, assert total pending
  notifications ≤ `SAFE_GLOBAL_NOTIFICATION_BUDGET`.
- **U7 parity test**: both apps import the same function; assert the rendered
  row values are equal for a fixed task fixture.
- **Past-due test**: a task 1 second in the past renders red and offers "Now".

## 8. Patterns worth importing, ranked by value

1. **Derived subtitles everywhere.** The single highest-value idea in the
   recording. Every option states its own consequence.
2. **Enumerated fire times.** "will fire at 12:00, 13:00, 14:00" beats any
   description of a rule.
3. **Past-due as colour, not as error.** §3.5.
4. **One control, three modes.** `Off | Count | Duration` collapses what would
   otherwise be three settings and an enable flag.
5. **State-following help text.** §3.4's AutoComplete.
6. **Inline expansion over navigation** for time selection; push only for
   genuinely separate concerns.
7. **Documented feature interactions.** §3.3's reset note.

## 9. Decisions

### 9.1 What "nag off" means — RESOLVED

Three concepts already overlap (`dismissedAt`, `escalationMode`, and the nag
fields). Shipping a fourth would be incoherent, so each gets exactly one job:

| Concept | Meaning | Field |
| --- | --- | --- |
| **PowerCircle / pause** | Mute this task entirely — no alert at all | `dismissedAt` (exists, already in UI) |
| **Nag preset** | How insistently it repeats *after* the first fire | `nagIntervalSeconds` + `nagMaxCount` |
| **Escalation** | Whether the interval tightens as you ignore it | `escalationMode` (orthogonal) |

**badgr's equivalent of "Nag-Me Off" is a "Just once" preset —
`nagMaxCount: 1`.** The task still alerts you once; it just doesn't badger.
That is the right semantic for this app specifically: badgr's whole premise is
badgering, so "off" must not mean "silent". Silent is what the PowerCircle is
for, and it already exists.

Consequence: **no schema change, and no new "off" state.** The preset list is
purely a set of `(nagIntervalSeconds, nagMaxCount)` pairs.

### 9.2 Duration formatting — RESOLVED

Confirmed from the frames at full resolution: **Due contradicts itself.**

| Source | 30 min | 90 min | 180 min | 220 min | 360 min |
| --- | --- | --- | --- | --- | --- |
| Preset subtitles (§3.3) | "30 min" | "90 min" | "3 hours" | — | "6 hours" |
| Custom subtitle (§3.3) | — | — | — | "3 hr, 40 min" | — |

The custom formatter switches to hours at 60 min and abbreviates ("1 hr",
"2 hr", "4 hr"); the preset formatter holds minutes to at least 90 and spells
out "hours". The same 90-minute duration would render two different ways
depending on which screen you're looking at.

**badgr uses one formatter everywhere:**

- Below 60 minutes → `"9 min"`, `"30 min"`
- 60 minutes and above → `"1 hr"`, `"2 hr"`, `"3 hr, 40 min"`, `"4 hr"`
- Exact hours omit the minutes component entirely
- Abbreviated (`hr` / `min`), comma-joined

This is Due's custom-formatter rule, which is the internally consistent of the
two. One function, `formatDuration`, and §7's boundary tests pin it.

### 9.3 Still open

1. **Name for intra-day recurrence.** "DayMinder" is Due's. Candidates: Rounds,
   Loop, Burst (already means something in `computeNagBurst` — avoid). Needs a
   name before Phase 5 writes it into the schema.
2. **Whether per-task snooze is worth the schema change**, given the global
   setting already exists and badgr is single-user. Cheap to add, but it is
   one more field on every sync payload.
3. **Melody/Sound/Alert Message** are listed in §3.2 but excluded from §0.
   Revisit only if per-task sound becomes a real request.
